# THE ONE LOCK. The image (Dockerfile), every CI job that installs Python packages
# (backend-tests.yml), and the dev venv all install with `-c constraints.txt`, so what CI tests is
# what the image ships. pyproject.toml pins each DIRECT dependency exactly as well; this file adds
# every TRANSITIVE one, which pyproject cannot pin (starlette, pydantic-core, httpx2, numpy, the
# nvidia-* CUDA wheels ...). Before this file those floated per build: the 2026-10-21 pod ran
# fastapi 0.158.0 while the floor said 0.115.0, and SQLAlchemy 2.1.6 compiled from source because
# it had been published that afternoon with no Linux wheel yet.
#
# Guarded by tests/unit/test_dependency_lock.py (pyproject == this file, nothing unpinned, every
# installer uses this file) and docker/check_installed_against_constraints.py, which the image
# build RUNS: an installed distribution missing from this file, or at another version, fails the build.
#
# Versions (operator rule, 2026-10-21 ~22:30 ET): the LATEST release of every package, as the
# resolver chose it, with mcp held to miStudio's pin (2.3.0 since 2026-10-21, also the latest;
# miLLM installs mcp only to load miStudio's registry, so the two move together). A version below
# the latest stands only for a technical cause, recorded in 0xcc/reviews/deps_sync_2026-10-21.md:
#   mpmath 1.3.0         sympy 1.14.0 (latest; torch's dependency) requires mpmath<1.4
#   cuda-toolkit 13.0.3 and the nvidia-* CUDA wheels
#                        torch 2.14.1 (latest; held equal to miForge's) requires them exactly
#
# Regenerate (Python 3.13, the image's platform; glibc 2.41, so manylinux_2_40 - at 2_28 the
# llama-cpp-python cu130 wheel, tagged manylinux_2_35, is invisible and an old sdist wins), with the
# holds, --upgrade, and wheels only (a release with no Linux wheel yet is not "latest" for us: it
# compiled SQLAlchemy 2.1.6 from source in the 2026-10-21 build). Then diff against this list, apart
# from wheel and the extras' pins at the end, which no resolver run includes. Strip the `==` from
# pyproject.toml first, or the resolver is bound to the current pins.
#   echo mcp==2.3.0 > holds.txt
#   uv pip compile pyproject.toml --extra dev --extra redis --extra gguf -c holds.txt --upgrade \
#     --only-binary :all: --python-version 3.13 --python-platform x86_64-manylinux_2_40 \
#     --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu130 \
#     --index-strategy unsafe-best-match --no-annotate --no-header
# To move a version: change it here (and in pyproject.toml if it is direct), re-run, and run the suite.
